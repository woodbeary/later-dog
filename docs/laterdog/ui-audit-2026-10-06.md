## Verified behaviours

- **Turn lifecycle and motion:** sending a message shows the mascot with "Thinking Ns" and a counting timer, animated dots in
  the header badge and sidebar row, and the composer switches to "<Bot> is working — Enter sends this into the running turn"
  with a stop control (05, 17). The reply replaces the working row; a shell task collapses into a "Worked for 8s" step that
  expands to the bot's progress messages (09).
- **Model and reasoning switching:** the thread picker offers engines (Grok / Claude / OpenAI), the account (Codex vs ChatGPT
  plan), models, and effort (Quick / Balanced / Deep / Max; Default / Low / Medium / High / X-High / Max for Claude). Chosen
  values reach the provider: the native event log shows `"model":"gpt-6-astra"` with `"reasoningEffort":"high"` for Otto's
  Deep setting and `"model":"gpt-5.6-sol"` for DevScout's bot-level default. A thread override and the bot default are
  separate, as the picker says.
- **Switching bots mid-turn:** with Otto working, opening DevScout leaves Otto's sidebar row pulsing (22); returning shows the
  header dots, the stop control, "Thinking 4s" and the "Otto is working" composer (23); the reply lands and the sidebar preview
  updates while the other bot is open (24). There is no separate thread object in this app: a bot is one conversation, with
  "Reply to message" quoting and group chats/teams for multi-bot work (the sidebar "+" menu offers New Bot, New group chat,
  Create team, Templates).
- **Presence:** an engine error flips the bot's avatar to a "!" badge in the sidebar and header until the next turn (08);
  mascots have idle/working/thinking/listening/sleeping expressions in the identity builder (15). New bots now wear later.dog's
  own dog body by default (25); existing bots keep the body they saved.
- **Bots:** New Bot dialog with starting roles, mascot builder, Soul / Skills / Memory / Routines / Access / Model /
  Permissions / Voice tabs (15, 16). The Coding-partner role pre-fills the name ("Dev"); typing appends to it. The later.dog
  roster from the bot-team guides (chief of staff, engineer, nightly audit engineer, reviewer, project manager, inbox
  manager, intel scout, gatekeeper) is in the same list (30); choosing "Engineer (cloud delegation)" fills the Soul with the
  job description that delegates through the later.dog tools and never merges (31).
- **Settings:** General (advanced mode, profile, language, default effort for new bots), Appearance (nine skins, fonts), AI
  (providers grouped Ready / Needs setup, 19 providers, "Check again"), Computers (remote access, domain, pairing), Account
  (people, activity export) (10, 11). More menu: find, copy/download Markdown, usage (tokens and context %), activity,
  inspector (12). Apps: Composio-backed connectors, not configured in this instance (13). Bot's computer: Computer / Browser /
  Files; the browser engine is not installed on this machine, with an in-app install button (14).
- **Workspace:** talks to the hosted Cloudflare supervisor — publishing host remote, 0/4 jobs, backends with truthful
  limitations, measured outcomes, Repository and Delegate dialogs (19, 20, 21). The header now also shows GitHub access as
  the supervisor sees it ("not signed in — set GH_TOKEN on the supervisor, then restart it", 29). No job was submitted
  during this audit because that credential is the operator's.
- **Agent → hosted supervisor through the saved connection:** with only `supervisor.json` in the data directory (no
  environment variables), the dev script started no local supervisor, and a Codex bot asked to call `laterdog_workspace`
  answered "There are 2 configured repositories: woodbeary/task-com-ai and woodbeary/txtclaw" — the MCP server, its token

- **Console:** no browser console errors across the session.

## Against xAI's "Designing Grok Bot" principles

Already present: bot roster instead of chat history; avatar presence that changes with state; a heterogeneous transcript
(messages, progress steps, error cards with Retry, structured widgets); routines (schedules, webhooks); group chats and teams;
a per-bot computer with status → side panel → takeover; connectors first; advanced controls hidden behind "Advanced mode".
Not yet: cloud-job cards that revive the chat when a job settles (wakeups exist server-side; the card is UI work), an
auto-review classifier in front of approval cards, the always-on coordinator (roadmap items 2 and 6).

## First run, as a new person sees it (2026-10-07, 17:00Z)

With an empty data directory the browser dev page lands directly in a seeded bot's chat (the welcome tour is reserved for
the desktop app's own window, by design), and a first message to a signed-out Claude produced a raw "Failed to
authenticate: OAuth session expired" card with only Retry. The desktop tour was reviewed step by step on
`onboarding-preview.html` (49, 50) and changed for launch: the greeting asks only for a name (no email, no "we'll let
you know when big things ship" — there is no mailing list) (51); the "Your phone" step is gone (no companion app yet);
the providers step leads with the subscription sign-ins a first-time person actually has — ChatGPT plan, Claude, Grok,
plus whatever is already Ready — and folds the other fourteen engines behind "Show 14 more providers" (52); and the error
classifier now reads Claude's "Failed to authenticate / OAuth session expired / could not be refreshed" as a sign-in
problem, which routes it to the sign-in card instead of Retry. Fixture tests cover each change; the tour itself still
needs a desktop launch to be seen end to end.

## The dogs, redrawn (2026-10-07, 9:30–10:45 PM PT)

The owner's verdict on the Grok-style dogs (one round head, eyes cut out of it): they "look like fish or a bear", and only
the Beagle read as a dog. A render confirmed why: every breed shared the round head; ears that hung beside it read as
fins and small upright ears as a bear's, and the cut-out eyes turned white on light backgrounds. Each breed is now its
own head drawn from data (`src/components/dog-breeds.ts`): a pale muzzle, a big nose and a mouth line, solid eyes with a
glint, and the breed's ears, head shape and markings, all in tones of the picked colour. The eight looks were drawn
against one review sheet (six colours, dark and light backgrounds, 56/40/32/26 px, all ten moods) rendered with
headless Chrome, and checked side by side in one colour so only shape and markings differ. The installed app (0.1.2
build) ships the new renderer; the app icon is the Retriever drawn from the same data.
