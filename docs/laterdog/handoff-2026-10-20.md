## Waits on you, in order

1. **Cloud home deploy.** Run "Cloud home delta image" on `main` with `base_tag` set to the image Cloudflare already
   holds (for the 2026-10-19 deploy that is most likely `81e55420b24942c087526e3550deaf59eb82e418-delta-4`, the only
   delta run on `81e5542`; check against `wrangler containers images list`). Copy the result to Cloudflare's registry as
   "How images ship now" in handoff-2026-10-19.md says, put its tag in `deploy/laterdog/home/wrangler.production.json`
   (that file still names `c4aa931e4b41`), and `wrangler deploy --containers-rollout=immediate`. This brings the
   old-phone fix and restore points. Homes running during that rollout keep their old Durable Object code until they
   sleep, so their first upgrade keeps no restore point; every later one does.
2. **Phone update.** Follow [later-dog-phone docs/ota-updates.md](https://github.com/woodbeary/later-dog-phone/blob/main/docs/ota-updates.md):
   `pnpm verify`, the fingerprint check against Build 6, then `eas update --channel beta`. Open a dog's chat on the
   iPhone and use the + menu: its Model and Account sections are SwiftUI, which only a phone shows.
3. **Claude Haiku first.** AI Gateway finds a stored key by its secret's name, so the key must be stored as
   `laterdog_anthropic_default`; the secret stored as `LATERDOG_ANTHROPIC` is never found. Store it as edge.md section 4
   says, run the edge dry run until the `ai-gateway` step stops saying the key is missing, then set `ANTHROPIC_FIRST` to
   `"1"`, run `pnpm run eval:haiku` and deploy `laterdog-computers`.
4. **Dashboard check.** AI Gateway > `laterdog` > Settings > Spend limits: each rule should read one day.
5. **From 2026-10-21.** Look at Security > Events for the managed ruleset; with no false positives, switch
   `managed-all-log` from log to block (edge.md, follow-up 1).

## Known quirks

- In a Claude cloud session ten tests fail that pass in CI, and fail the same way there on unchanged `main`. Three see
  the session's own proxy variables (`HTTPS_PROXY` and friends): in `server/drivers/codex.test.ts`,
  `server/mcp-remote-proxy.test.ts` and `server/mcp-gate-config.test.ts`. One expects a file made unreadable to stay
  unreadable, which root can still read: `server/checkpoints.test.ts`. The rest are in `server/workspace-backup.test.ts`
  (a 20 s timeout), `server/cli-stop.e2e.test.ts` and `server/drivers/chat-mcp-tools.test.ts`.
