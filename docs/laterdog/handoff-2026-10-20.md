## Waits on you, in order

1. **Sign-in alerts.** In `cloudflare/control-plane`: `pnpm exec wrangler secret put ALERT_EMAIL --config
   wrangler.production.json` (type the address that should get them), then `pnpm exec wrangler deploy --config
   wrangler.production.json`. Nothing else in that Worker changed since its 2026-10-19 deploy.
2. **Cloud home deploy.** The image is built. "Cloud home delta image" run 5 on `862f740`, with `base_tag` set to
   `81e55420b24942c087526e3550deaf59eb82e418-delta-4` (the only delta run on `81e5542`, so most likely what the
   2026-10-19 deploy holds), made `ghcr.io/woodbeary/later-dog-home:862f740d5df7a4e067d156792ebcf4e15ab50781-delta-5`:
   28 files changed and 1 deleted in an 8.0M layer, and the boot, pairing, first trip and reaping checks passed. Check
   that base against `wrangler containers images list`, and run the workflow again with the tag listed there if it
   differs. Copy the result to Cloudflare's registry as "How images ship now" in handoff-2026-10-19.md says, put its tag
   in `deploy/laterdog/home/wrangler.production.json` (that file still names `c4aa931e4b41`), and
   `wrangler deploy --containers-rollout=immediate`. This brings the old-phone fix and restore points. Homes running
   during that rollout keep their old Durable Object code until they sleep, so their first upgrade keeps no restore
   point; every later one does.
3. **Phone update.** Follow [later-dog-phone docs/ota-updates.md](https://github.com/woodbeary/later-dog-phone/blob/main/docs/ota-updates.md):
   `pnpm verify`, the fingerprint check against Build 6, then `eas update --channel beta`. On the iPhone, open a dog's
   chat and tap the line above the composer (it opens Model), then open AI Accounts twice: the second time is instant.
4. **Claude Haiku first.** AI Gateway finds a stored key by its secret's name, so the key must be stored as
   `laterdog_anthropic_default`; the secret stored as `LATERDOG_ANTHROPIC` is never found. Store it as edge.md section 4
   says, run the edge dry run until the `ai-gateway` step stops saying the key is missing, then set `ANTHROPIC_FIRST` to
   `"1"`, run `pnpm run eval:haiku` and deploy `laterdog-computers`.
5. **Dashboard check.** AI Gateway > `laterdog` > Settings > Spend limits: each rule should read one day.
6. **From 2026-10-21.** Look at Security > Events for the managed ruleset; with no false positives, switch
   `managed-all-log` from log to block (edge.md, follow-up 1).

## Known quirks

- In a Claude cloud session ten tests fail that pass in CI, and fail the same way there on unchanged `main`. Three see
  the session's own proxy variables (`HTTPS_PROXY` and friends): in `server/drivers/codex.test.ts`,
  `server/mcp-remote-proxy.test.ts` and `server/mcp-gate-config.test.ts`. One expects a file made unreadable to stay
  unreadable, which root can still read: `server/checkpoints.test.ts`. The rest are in `server/workspace-backup.test.ts`
  (a 20 s timeout), `server/cli-stop.e2e.test.ts` and `server/drivers/chat-mcp-tools.test.ts`.
- Phone CI in later-dog-phone runs only by hand, and every run since 2026-10-18, run 16 on `20fd841` included, has
  ended within seconds without starting a step or writing a log. It says nothing about the code; `pnpm verify` on a
  computer is the phone's check (ota-updates.md).
- `fix/old-phone-new-thread` landed as `20d1828`: every file it touched matches `main`, so the branch can be deleted.
- The rest of [handoff-2026-10-19.md](handoff-2026-10-19.md) "Known quirks" still holds.
