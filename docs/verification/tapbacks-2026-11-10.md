# Dog tapbacks, November 10

The built-in `react` tool patches the latest person-authored text message in
its current active conversation path, or a named text message in that path.
One emoji is accepted. Another call replaces that dog's previous reaction;
other people's and dogs' reactions remain. The existing persisted reactions
and message.patch broadcast carry it to every client.

Dogs with the tool are told that a plain acknowledgment needs a reaction
and no reply, including acknowledgments sent during ongoing work. The on-it
and steer notes make that exception explicit. A reacting turn's emoji-only
assistant output is omitted from both the saved transcript and public runtime
stream. Turns with substantive text still keep that text. A patch emits no
notification, and a completion with no text emits none either.

Desktop and phone anchor compact tapbacks to the top corner of the bubble.
The phone keeps the reaction buttons beside the message press target within
a shared anchor, preserving long-press and avoiding nested press targets.

## Isolated checks

On Patch's cloud computer:

- `pnpm typecheck` and `pnpm lint` pass with no warnings in the home repository.
- `pnpm exec vitest run server/tapback.e2e.test.ts` launches a separate fixture
  with `launchVerificationServer`, a fresh temporary home, and the scripted
  fake engine. The tool is advertised and called through the real MCP proxy.
  The saved transcript contains the person's message with the dog's reaction
  and no bot text bubble. SSE records the message.patch and contains neither
  a notification nor emoji-only assistant text. A second turn replaces the
  reaction and keeps a substantive reply. Invalid emoji and a missing target
  are refused. No production messages are mutated for these checks.
- Tapback unit checks cover emoji validation, target selection, replacement,
  quiet text, guidance and empty completion notifications.
- ChatView and GroupView renderer checks inspect the actual DOM, parent bubble,
  corner position, accessible names and read-only handling.
- Phone `test/tapbacks.test.ts` renders the real reaction component with native
  host mocks, checking corner offsets, grouping, accessible labels and empty
  rendering, and checks its placement in the message anchor.
- Tool catalog source and packaged golden checks include `react`; the chat MCP
  policy check confirms only the built-in tool skips the engine's approval.

The retained first attempts include a Unicode-regex lint warning (fixed using
single graphemes) and an overly strict serialized GroupView assertion (replaced
with DOM assertions). No physical phone or installed desktop visual check is
claimed by these tests. Release identifiers are recorded after publication.
